## Header format + compression, third pass

User: the source line repeats itself (page id appears again inside the url), drop
`ingested`, drop the `created` and `source:` keys — position carries the meaning — and
add a compression rate.

New line, no keys: `{created date} | {compression}% | {notion url}`
Changed in three places so they cannot drift: the SEO page, the skill, and the hard rule
in `my_wiki/CLAUDE.md`. The skill's own verify grep still hunted the old `source:` string;
fixed to match the new shape.

**Compression = distilled body chars / source chars.** Measured against the fetched page
text with Notion's XML table/toggle markup stripped — measuring against the raw fetch
would flatter the number.

First measurement was **64%**, which exposed the real problem: the "distillation" was an
edit, not a distillation. Added a threshold to the skill and the rules — **above ~40% is a
copy, cut again** — and re-distilled to **37%** (3,847 chars body vs 10,324 source).
What went: the tools table, per-step how-to detail, repeated framing. What stayed: every
hard number, both case studies, the named sources, and the whole "gaps here" list.

Lesson worth keeping: without a measured ratio, "cave-man style" drifts into paraphrase.
The number is what makes the rule enforceable.
