## Decided
1. **MCP, not an API-token fetcher.** Matches the user's project checklist, zero code.
   Compared both; the fetcher's one real advantage is a raw `.json`/`.md` archive on disk,
   which MCP cannot give. Accepted: provenance is a Notion URL, not a local file.
2. **Grant = the inbox database only.** Turned out the whole workspace is just that.
3. **Never write back to Notion.** 0th is read-only. Hard rule in `my_wiki/CLAUDE.md`.
4. **Ownership: each fact in ONE file.** `my_wiki/CLAUDE.md` = what the tree is (auto-loaded,
   must stand alone). `wiki-update/SKILL.md` = how to write into it (loaded on invoke).
   `0th/queue.md` = data only. HANDOVER points at the skill instead of restating it.

## Things that bit, in order
1. **`claude mcp add` does not hot-load.** Servers load at session start. Config was correct;
   `/mcp` showed nothing. `/exit` + `claude --continue` fixed it. **Skills behave the same** —
   hit twice, once for the MCP server and once for a freshly written skill.
2. **OAuth on a headless box does not work the documented way.** The flow wants a browser on
   `localhost:3118`; this box has none, and the notebook's localhost is a different machine.
   Notion's server carries in-band auth: `authenticate` prints a URL, user opens it on the
   notebook, **the callback page failing to load is the expected state, not a problem**, user
   pastes the whole address-bar URL back, `complete_authentication` consumes it. No tunnel.
3. **The Notion MCP server ships instructions telling the model to push content INTO Notion.**
   Directly against this design. Ignored, and written into HANDOVER so the next session does.
4. **Grant is read-WRITE, 29 tools.** No read-only toggle — access is bounded by which pages
   are granted, not by permission level. Only the CLAUDE.md rule stops a write.
5. **The inbox has no last-edited field.** Schema is `Name` + `createdTime`, so an edited page
   looks untouched and CHANGED can never fire. Fix is Notion-side, nothing to build here.
6. **Split one Notion page into 15 files.** Followed the old hard rule "one page = one idea".
   Wrong: the user wants 1 Notion page -> 1 file. The 15 titles were the right *decomposition*
   — they belong as `#tags` inside one file. Rule rescoped: "one page = one idea" starts at
   **2nd**, where splitting is actually the work. 1st mirrors Notion 1:1.
7. **"Cave-man style" drifts into paraphrase without a number.** The first distillation read
   as finished at **64%** of source — an edit, not a distillation. Added a measured ratio to
   the page header and a threshold: above ~40% is a copy. Re-distilled to **37%**.
8. **A hand edit to the tree does not announce itself.** The user flattened `0th/{n,i,r}` to a
   single `0th/queue.md`. Nothing failed at the time — but `wiki-update` pointed at the old
   path in four places and would have failed the next morning mid-routine, or quietly
   recreated `0th/n/`. After any structural change, grep the old path across skill, rules
   file and HANDOVER.
