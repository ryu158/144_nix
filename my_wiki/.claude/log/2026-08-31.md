## Rule changes

1. **Always hub plus children.** Every Notion page, even a one-idea page (hub + 1 child).
2. Hub `{YYMMDD}_{HHMM}_{title}.md`, child `{YYMMDD}_{HHMM}_{nn}_{idea}.md`.
3. `nn` is the child's position in the hub list.
4. Hub holds no prose — tag, header, one `>` gist, numbered bare links.
5. Child title never repeats the hub title. `# Rader`, not `# FFT — Rader`.
6. Body style is the reform 8 rules. Numbered lists, one sentence each.
7. **No tables in a content page.** A source table becomes a numbered list, one item per row.
8. Tables survive only in `0th/queue.md` and `index.md`.

## Bugs found and fixed

1. **Queue trap.** A `done` row whose hub file is gone was unreachable. `== synced` skips it,
   and blanking `synced` fires the bootstrap branch, which also skips. Rows must be
   **deleted** so they read `absent` -> NEW. Added as a verdict row.
2. **Child test was dead.** `*__*.md` no longer identifies a child. Replaced with content
   tests: child has a `< [[1st/n/` line, hub has the `| N% | https://` line.
3. **Greedy sed.** `sed 's/.*1st/1st/'` collapsed every link path to `1st`, producing a
   phantom DEAD LINK. Fixed to `-oh` plus an anchored strip.
4. **Hub-child check used the wrong prefix.** It looked for `{hub basename}_01_` when
   children are `{timestamp}_01_`. Now cuts the timestamp with `cut -d_ -f1,2`.
5. **Tag regex missed its own tag.** `^#[A-Za-z]` never matched `#1st`, which leads with a
   digit, so the "no stray tags" check silently passed on everything. Widened to
   `^#[A-Za-z0-9]`.
6. **Queue format was undocumented.** Columns and scan-line shape existed only inside the
   gitignored `queue.md`. Now written into the skill.

## Syncthing password — question answered

1. Asked how to apply a hand-edited user/password in `~/.local/state/syncthing/config.xml`.
2. First answer given was **wrong**: claimed `syncthing serve` hashes a plaintext
   `<password>` at startup. It does not.
3. Verified in source. `SetPassword` does hash plaintext, but config load never calls it —
   `prepare()` only reads `GUI.Password` to test whether auth is on. Login is strictly
   `CompareHashedPassword`, no plaintext fallback. A plaintext field locks you out.
4. The correct tool already exists in this repo: `servers/syncthing/flake.nix` ->
   `st_ps_update`. Its comment states the same finding.

```
cd servers/syncthing && nix run .#st_ps_update
```

5. It kills by port owner (never `pkill -f syncthing`), blanks the field so `generate`
   cannot skip as "unchanged", hashes via stdin, restarts, then POSTs the credentials to
   prove the login works.
6. Syncthing here is **not** a NixOS module — the flake only packages the binary and these
   scripts. So nothing rewrites `config.xml` on rebuild.
7. `systemctl` does not apply on this box. Start is `nix run .#st_start`.
