## Change 2 — 2nd tag index

1. New section `## C — 2nd tag index` in the skill, between B and Close the run.
2. Runs after B, over every NEW and CHANGED page.
3. Candidate tags for a trigger page = its own Notion tags, plus any vault tag that is a
   whole word in the trigger page's title.
4. Group for a tag = every hub matching by tag line **or** by basename word. Split the
   basename on `_`, case-insensitive.
5. Under 2 hubs -> build nothing. A one-item list is noise.
6. Name `{trigger YYMMDD}_{HHMM}_{tag}.md`. One file per tag. Hubs listed oldest first.
7. Links only. **No compression rule** — there is no distilled body to measure.

### The naming cost, accepted knowingly

1. The timestamp is the **trigger page's** `createdTime`, chosen by the user.
2. The alternative offered was the oldest hub in the group, which never moves.
3. Cost of the choice: the next `#SEO` page writes a second file under a new date, and
   two indexes for one tag exist.
4. So every run must report the older index superseded. It is never auto-deleted.
5. Check script gained a `TWO INDEXES FOR ONE TAG` block to catch it.
