## favicon, and a 404 that had been ignored by name

The user hit `GET /favicon.ico 404`. It was HANDOVER's oldest open gap, parked
since 2026-08-21 because "fixing it needs an icon decision first".

The mark drawn is the site's one idea: known points, and a curve estimating what

site's most recognisable one, so no new colour entered the system.

favicon.svg is the source. The .ico was generated from it: 16/32/48 px rendered

was what actually worked. **Reading the PNG was the only thing that caught it**;
the file sizes looked plausible.

The part that mattered more than the icon: `collectConsoleErrors` had been
ignoring `/favicon.ico` by name since 2026-08-21. That ignore is now deleted, so
every "the console is quiet" assertion in the suite depends on the file really
being served. The suite went 65 -> 71 and those assertions pass without the
exemption, which is the actual proof the 404 is gone.

## The backend, and the button wired to it

`webUI/app.py` is one backend for the whole site, not one per topic — the user
was explicit about that. Routes are `/api/<topic>/<method>`, built from each
topic module's own `METHODS` table, so a new method is one line in the topic
file and none in `app.py`. The math sits next to its topic and imports no Flask,
which keeps it callable without a server.

The reference server the user pointed at supplied the shape — `request.get_json()`,
a table of strings in and out, helpers at the bottom. Four things in it were
deliberately not copied, each for a reason worth keeping:

1. `host='0.0.0.0'` binds every interface; ours binds loopback.
2. `CORS(app)` needs `flask_cors`, which is not in the flake.
3. `np.arange` excludes the endpoint, so 0/1000/1 would give 1000 points where
   `interp_engine.ts` gives 1001. The two pages would disagree at the last x.
4. Bare `np.interp` **clamps** outside the domain and returns the edge value
   silently. Our contract is a blank cell, so linear masks the outside back to
   NaN explicitly and the scipy interpolators take `extrapolate=False`.

The agreement check is the one that matters: demo dataset, range 0/1000/1,
Python against the compiled `interp_engine.js` — 1001 rows both sides, max
absolute difference **0.000e+00**.

`nix run .` works now, for the first time in this repo's history. It failed once
more before that, with `can't open file .../app.py`: **flakes copy only
git-tracked files**, and app.py was untracked, so the store copy did not have
it. Staging it was the fix.

## Demo data that shows the difference

The user ran all four methods on the advanced page and could not tell them
apart. Fair: the page was seeding the basic calculator's 50-point demo, which is
smooth enough that linear, cubic, PCHIP and Akima agree to about 1e-2. A page
whose whole purpose is choosing between methods was opening on data where the
choice does not matter.

Four candidates were measured before proposing any of them, rather than picked
by eye:

1. The blog's own step (gen_figs.py:38) — 13% separation, and only cubic moves.
2. The blog's outlier (gen_figs.py:128) — 14%, again only cubic.
3. Runge on 9 equispaced points — 10%. Weaker than expected.
4. Two plateaus with sharp edges — 20%, and all four methods behave differently.

The user took the fourth: x 0..10, y 0/100/0/40/0. Measured live through nginx
afterwards: cubic runs -13.56..119.63, akima -7.14..112.50, linear and pchip
stay inside the data's 0..100. That is the article's own argument made runnable
— gen_figs.py:97 annotates "overshoot" on exactly this behaviour.

The level object in spec.json now owns `dataset` and `range` alongside the
`methods` list it already had, so the advanced page differs from the basic one
in data without either hardcoding anything. The basic page is untouched on
purpose: demo.spec.ts asserts its seeding and fixture.spec.ts compares 1770
cells against an independent implementation.

One new test earns the change. It posts the demo data to /api/interpolation/cubic
and /pchip and asserts cubic exceeds the data maximum and dips below its
minimum, while PCHIP does neither. Swap in smooth data later and it fails,
instead of quietly shipping a comparison page with nothing to compare.

## The manual opens on hover now

The user wanted the instruction toggle to open on hover. Hover REPLACING click
would have broken two groups: a touch device reports no hover at all, so the
manual becomes unreachable on a phone, and a keyboard user cannot produce one.
So hover was added on top, gated behind `(hover: hover) and (pointer: fine)`,
and `<details>` keeps doing the opening.

Chosen behaviour: hover in opens, hover out closes, a click pins it open, and
Escape or an outside click closes and unpins. Two delays exist for real reasons
— 120 ms before opening so brushing past does not throw a panel over the grids,
220 ms before closing so a brief exit does not snatch it away mid-read.

Two design points that are easy to get backwards:

1. A click on an already-hover-opened panel is intercepted. Native `<details>`
   would toggle it SHUT — the exact opposite of what that gesture means.
2. Escape does not reopen on the hover that is already there. The pointer has
   not moved, so no `mouseenter` fires. My first test assumed it would and
   failed; the component was right and the test was wrong. Corrected to move the
   pointer away and come back, and it now asserts the stay-shut behaviour too.

This was the second use of the panel, so it was extracted to
`dev_basic/how-to.ts` per the CLAUDE.md rule rather than having the hover logic
written twice. Neither controller owns panel code any more. Being shared, it
cannot know its topic, so the element declares it: `data-slug` and `data-level`.

That extraction changed the analytics payload — `howto_open` now carries `level`
alongside `slug` — which broke an assertion in analytics.spec.ts. Real change,
caught properly, and the test now reads the slug from spec.json rather than a
literal.

The bigger analytics risk with hover is volume: it fires on every pass of the
pointer. The event is deduped to one per page load, and a new test hovers the
panel open and shut three times to assert exactly one event.

While updating this HANDOVER I anchored a replacement on `s.index("## Next")`.
That string's first occurrence is inside the sentence "Pick up ## Next at the
bottom of this file", so everything from Resume here to EOF was replaced and the
file was cut to 13 lines. Recovered with `git checkout --`, then redone by

**Yesterday's log records this exact mistake** — a renumbering script that
anchored on "## Next" and matched the reference to it in prose. Reading the log
was the first thing done this session, and the lesson still did not transfer.
The fix is mechanical, not a matter of care: match a heading by `line.strip() ==
name` and assert exactly one hit, never by substring search.

A second, smaller version of the same failure: a renumbering loop that replaced
`"\n{n}. "` across the whole file silently damaged two unrelated lists. Restart
the counter at each `## ` heading and touch only the sections being edited.
