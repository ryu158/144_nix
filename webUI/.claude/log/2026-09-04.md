## Explaining app.py, and the question that was actually interesting

Most of the morning was the user reading app.py and asking it back to me a piece
at a time. Two of their questions were sharper than the code's own comments:

**"How does app.run(host, port) become _run(topic, method)?"** It does not.
`app.run` is Flask's accept loop, entered once and never returned from.
`_run` is ours, called per request from inside it. The names collide and nothing
else does.

**"Step 4 has to come before 2 and 3, because without 4 there is no info about
topic and method."** This is the good one, and the answer is that there are two
different knowings. *Which* methods exist comes from the METHODS dict in the
source and is fixed at import. *Which one this caller wants* comes from the URL.
`_register` only needs the first, so it runs with the network unplugged.

Their mental model matches a real and valid alternative — `@app.route('/api/<topic>/<method>')`
with the values extracted per request. The repo took the loop instead so an
unknown name dies at routing rather than inside a handler, and so `app.url_map`
lists exactly what exists instead of a wildcard. Both are one line per new
method; the difference is where a bad name is caught.

The user wrote their own notes from that conversation as `webUI/app_py.md`.
Untracked, their file, not a rules file.

## CSV / TSV import and export

The advanced page could only take data in by paste and give it out by selecting
the output grid and copying. Anyone working from a file had no way in or out.

Four decisions were put up front and all four survived: import fills the input
grid and export saves the output grid; parsing matches grid.ts `_onPaste`
exactly; advanced page only, so it stays a first use under CLAUDE.md rule 4; and
no header row on export.

The parsing decision is the one worth defending. `_onPaste` sniffs tab-vs-comma
on the first line and splits, and it does not handle a quoted field containing a
comma. Copying that limitation deliberately keeps file and clipboard in
agreement. Fixing it in the import path alone would mean the same bytes give two
different grids depending on how they arrived.

Two existing mechanisms did the work that looked like it needed new code:
`setData` emits `change`, so re-plotting and the `demoPristine` clear happen
through handlers that already exist; and `setData` hard-resets dimensions, so an
import replaces the demo wholesale and needs no equivalent of the capture-phase
paste clear.

One real trap: `importFile.value` must be cleared BEFORE the await. Leave it set
and picking the same file twice fires no change event, so the second import
silently does nothing.

## Then the export design changed

Shipped first as two buttons, `export CSV` and `export TSV`, because a Blob plus
`<a download>` cannot ask the user anything — the browser writes the file with
whatever extension the code set.

The user asked for one button with the type chosen in the file explorer. That is
a different API: `window.showSaveFilePicker`, which opens a real Save-as dialog
with a type dropdown. It is Chromium-only, has no polyfill, and Playwright cannot
drive a native dialog. All three costs were stated before proposing it.

The user chose the fallback that loses nothing: one button everywhere, and on
Firefox and Safari a format `<select>` unhides beside it.

The inversion at the centre of this is worth stating plainly. **The format now
comes back from the handle, not from the page.** `showSaveFilePicker` returns
the name the user typed or picked, and its extension decides the delimiter. A
test asserts exactly that: the page never chose tsv, the dialog did.

Three details that are easy to get wrong:

1. The picker must be called with no `await` above it in the click handler.
   Chromium needs an unconsumed user gesture and one awaited tick spends it —
   after which the dialog silently never opens. `grid_2.getData()` is
   synchronous so this holds today, and the code says why.
2. `window.showSaveFilePicker` is read fresh on every click rather than captured
   at load, so a test can add or remove it per page.
3. AbortError means the user pressed Cancel. It is swallowed: no status change,
   no console error, and no `csv_export` event for a save that never happened.

`types/globals.d.ts` gained a minimal File System Access declaration — four
members, because TS 5.4's DOM lib ships none and the full spec types are far
more than the export path touches.

## Own mistake worth remembering

Ran `npx tsc --noEmit` out of habit. `tsc` is not an npm dependency here — it
comes from the flake — so npm went and fetched an unrelated 12-year-old package
called `tsc` from the registry, printed "This is not the tsc command you are
looking for", and exited 0. The typecheck never ran and the exit code said fine.

Nothing was damaged: package.json and package-lock.json were unchanged and
node_modules had no new entry, both verified. But CLAUDE.md says no new
dependencies without permission, and `npx` will install one to satisfy a typo.
**Use the flake's `tsc` directly. `npx` is for Playwright and nothing else.**
