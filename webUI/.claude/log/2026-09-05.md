## The plan, and the two questions that shaped it

The user answered the whole queue: app.py stays manual, no systemd unit; the
site moves to /scientific_cal; PC and large tablet are the target with mobile
best-effort; FFT waits; and CSV comes to the basic calculator too.

Two decisions were put back to them because they changed the shape of everything
after.

**Real directory or virtual prefix.** A prefix nginx strips would have been a
smaller diff — files stay put, each page gets `<base href="/scientific_cal/">`.
They chose the real directory, and it is the better answer for a site meant to
grow: repo layout mirrors URL layout, absolute paths keep working once prefixed,
no `<base>` subtlety, and the second section is a second directory with no nginx
work at all.

**Cutover.** A two-deploy sequence would have had zero downtime — deploy a
config whose page blocks try the new path and fall back to the old, then move
the files under it. They chose one deploy and a short outage. Their call, and
the outage window is theirs to close.

## applyColumnLock was wrong, not unproven

The handover flagged this branch as untested. It was worse than that.

`setData` hard-resets `numCols` from the incoming array, so a locked grid moved
in **both** directions. The existing code truncated a too-wide file, which is
what a paste does. Nothing padded a too-narrow one — so importing a 2-column
file into the basic page's 4-column locked grid would have taken the grid down
to 2 columns, while a paste of the same bytes left it at 4.

It now squares every row off to exactly `numCols`. Too wide still alerts,
matching grid.ts. Too narrow pads silently, because a narrow paste says nothing
either and the blanks are what an empty column looks like.

The test for it was run against the pre-fix code and observed to fail with the
grid two columns wide. A regression guard that has never been seen to fail is a
guess about what it guards.

## The scaffold, and what it must never own

After CSV landed on both pages, `page.ts` and `page_adv.ts` differed only in how
they compute. `dev_basic/calc-page.ts` took the rest: finding the markup, both
grids, the chart, `plotBoth`, `setStatus`, the `initCsvIo` call, the demo seed,
and the capture-phase paste clear. 134 -> 61 and 196 -> 94 lines.

The single idea that made the two demo-seeding blocks collapse into one is that
`level` was already doing three jobs — naming the analytics level, picking
`spec[level].dataset` and `spec[level].range`, and tagging the console warning.
The basic page has no `calculator.range` in spec.json, so its Output X inputs
keep their HTML values through exactly the same code path the advanced page's
`advanced.range` uses. No special case.

**The constraint is that the scaffold owns no math and loads no engine.** The
advanced page's status line names the method the server ran. A client-side
fallback reachable from shared code would make that line a lie, which is the
whole reason `page_adv.ts` was written the way it was.

Proof it was a pure refactor: 105/105 with zero test edits, and the client/API
agreement re-measured at 1001 rows both sides, max absolute difference 0.000e+00.

## The move

Under `scientific_cal/`: index.html, home.ts/.js, dev_basic/, src/, topics/.
Left at the root: app.py, tests/, types/, tsconfig.json, robots.txt, sitemap.xml,
and the favicons — a browser asks for /favicon.ico whatever the page path is.

A new umbrella page at `/` lists sections. It carries the Google Search Console
verification meta tag, which has to live at the property root; leaving it only
on the section index would have un-verified the property.

Two things about the backend are worth keeping.

1. **Flask's routes did not change.** They still start with `/api/`. The nginx
   block does the mapping: `proxy_pass http://127.0.0.1:<port>/api/`, with the
   trailing `/api/` doing the substitution. Drop that suffix and every call 404s
   inside Flask. Same trick the /syncthing/ block has always used.
2. **The unprefixed /api/ block is kept.** The backend belongs to the site, not
   to one section, and `/api/health` is how a 404 (no route) is told apart from
   a 502 (route exists, nobody answered).

That second decision has a sting, and it is the CORS-adjacent trap. `page_adv.ts`
called `fetch('/api/…')` with a leading slash. Post-move that resolves to the
unprefixed block — which is kept, so it would have **worked**, and a wrong path
would have passed every test. Every leading-slash path was swept for that
reason, `src/shell/seo.ts`'s spec.json fetch included.

CORS itself needed nothing. Page and API share an origin before and after, and
app.py already records why `flask_cors` is absent. If the API ever gets its own
origin the fix is an exact-origin `add_header` in the nginx block — never a
wildcard, and never in app.py, which has size and row caps but no auth.

## Own mistake worth remembering

Rewriting the handover's queue, the anchor was `s.index('## Next')`. The first
occurrence of that string is inside "Resume here" — *"Pick up ## Next at the
bottom of this file"* — so the replacement truncated the file from line 7 down.
278 lines to 15, and every handover edit made this session went with it, because
none of it was committed.

Recovery was `git show HEAD:` and re-applying everything in one scripted pass.
Nothing was lost that was not reconstructible from the session.

**Anchor on `rindex` when the marker is a heading that the document also
mentions in prose.** More generally: a document that refers to its own structure
cannot be edited by first-match.
