## Blog rewritten from interpolation.zip

### What arrived
1. User dropped `topics/interpolation/interpolation.zip` into the topic folder: a
   5-method article (linear, cubic spline, PCHIP, Akima, FFT), 7 SciPy SVG figures,
   a markdown source, `gen_figs.py`, `build_html.py`, and a 271 KB standalone HTML.
2. Built outside this repo. It carried its own CSS theme, its own nav row, a
   jsDelivr MathJax tag, and figures base64-inlined into the HTML.
3. Its `canonical` pointed at `/interpolate_methods_blog` — a URL that does not exist.

### Decisions
1. Same URL `/interpolate_blog`, full replace of the article body. So: no nginx
   change, no new sitemap entry, no new level.
2. Its styling, nav, and CDN tag all dropped. Page wears the site header and tokens.
3. MathJax self-hosted. `tex-mml-svg`, not `tex-mml-chtml` — SVG output needs no
   web-font directory, so self-hosting is one 2.1 MB file instead of a font tree.
   Estimated 1.2 MB in the plan; it is actually 2.1 MB. Said so rather than let the
   plan's number stand.
4. Figures served as files. `figs/` is 200 KB, and the HTML fell 271 KB -> 20 KB.
5. `gen_figs.py` and `interpolation_blog.md` archived. `build_html.py` and the zip deleted.

### How the port was done
Did NOT re-author the article by hand — the site has no markdown tool in flake.nix,
and hand-converting ~30 equations invites silent typos. Instead reused the zip's
already-rendered body: stripped its `<h1>` and `<nav>`, then swapped each base64
`<img>` for a file path by **matching the decoded SVG against the files on disk**,
not by position. All 7 matched.

### Two-h1 defect closed
The page had `<h1>Interpolation❓</h1>` in the header plus `<h1>Linear
Interpolation</h1>` in the article. Dropping the zip's own `<h1>` left exactly one,
with `<h2>` sections under it — no heading demotion needed. `nav.spec.ts:15` asserted
the article h1 text; it now asserts the header's.

## Calculator: "How to use this" panel

### Why
`<p class="page-intro">` sat pinned to the bottom of the viewport. Nobody looks
there, and it permanently cost 2-3 lines of grid height.

### The constraint that shaped it
`seo.spec.ts:107` asserts the visible body text contains "csv", "tsv", "copy and
paste". **Playwright's `innerText` does not see inside a closed `<details>`.** So
those words live in the `<summary>`, which is always on screen. That kept the test
green with no edit, and kept the claim honest — the words are visible, not buried.

### On the SEO framing
User's first ask was a hidden block "so crawl bots find it easy while the user
isn't bothered". Said plainly that a collapsed accordion is fine and indexed
normally, but text written for bots only is what Google's spam policy calls hidden
text, and the repo already took that stance in `interpolate_cal.html`'s own comment.
User then redirected to a real manual, which is the version that shipped.

### Build
1. Native `<details>` does the opening — no JS to reveal it, so the manual is in the
   HTML before any script runs.
2. Open, the body is absolutely positioned and floats over the grids. `.how-to` owns
   the positioning context, so `#app` is untouched and no other page inherits it.
3. `max-height: min(60vh, 520px)` with its own scrollbar. Without it a long panel on
   a short screen runs off a page whose body is `overflow: hidden`.
4. `page.ts` gained a second IIFE with its own guard, above the calculator one:
   dismiss on outside click, dismiss on Escape, `howto_open` event.
5. The manual names no method and no default range. spec.json owns those.

## Calculator: demo data
1. 50 points, x 0 -> 1000, one y series, stored in spec.json `dataset`. The chart
   plots it on load.
2. Seeding fires no analytics event — `grid.on('change')` runs `interpolateAndPlot`,
   which only plots while the output grid is empty. Had it fired `interpolate_run`,
   two analytics tests asserting "exactly one event" would have broken.
3. **The trap**: `grid.ts:_onPaste` overwrites cell by cell, it does not clear. A
   seeded grid plus a 2-row paste leaves 48 demo rows silently mixed into the result.
4. Fixed with a **capture-phase** listener on `#gridContainer` — it must run before
   grid.ts's own handler on the hidden input. Bubble phase would be too late.
5. Fires once. After any change the grid is not pristine, so a second paste behaves
   normally. Both halves asserted.
6. The spec.json fetch is async, so seeding is skipped if the grid is no longer empty
   when it lands. A visitor who pasted during the fetch keeps their data — and this
   is also why all 41 existing tests stayed green without edits: they paste at once.

## Centring, and the width:100% trap
1. User wanted blog then home centred, text still left-aligned.
2. Added auto side margins to `.post`, `.topic-list`, `.dev-section`, and
   `.app-header` on both page types. No `text-align` anywhere.

   item's default stretch, so the blog header shrank to its buttons — 555px instead

   with `width: 100%`. The "share the same left edge" assertion is the only reason
   that surfaced before the user saw it.
