## SEO - root cause found and fixed
- User asked why Google returns nothing for the calculator's exact title, while "ryuora144 interpolation" works.
- ROOT CAUSE: topic pages had NO <title> element at all. Title was JS-injected by seo.js, and seo.js derived the slug from the path (/^\/topics\/([^/]+)\//), which never matches the public url /interpolate_cal. It bailed out. Google crawled titleless pages.
- Fixed earlier in the day by adding data-slug; then made tags static so crawlers never depend on JS.
- DevTools HID this - it shows the post-JS DOM. `curl <url> | grep '<title>'` is the only honest check. Recorded in CLAUDE.md + topics.md + SKILL.md.
- Added to both topic pages: static title, meta description, viewport, og:, twitter:, JSON-LD (Article / WebApplication).
- seo.js now console.warns when a static tag differs from spec.json (drift guard), instead of silently overwriting.
- robots.txt + sitemap.xml created. robots.txt deliberately does NOT block /dev_basic/, /src/, or topic JSON - Google renders before indexing, blocking those breaks the render and empties the homepage topic list.
- Internal links repointed from /topics/.../*.html to public urls. Those raw paths are duplicates and robots-disallowed.
- Calculator body had almost no crawlable text. Added a short static line carrying the terms the description promises (copy/paste, CSV, TSV, spreadsheet, multiple lines, vector, matrix). Later moved to page bottom on request and shortened 282 -> 182 chars.
  - Constraint: must stay INSIDE #app. body is overflow:hidden and #app is height:100%, so anything after #app is clipped = hidden text = Google penalty.
- meta keywords NOT added - Google ignores it since 2009, Bing treats stuffing as spam. Terms went into title/description/body instead.
- Blog SEO broadened "Linear Interpolation" -> "Interpolation" per user (advanced page coming). Calculator description left claiming linear only - the calculator really is linear-only, overpromising would raise bounce.
