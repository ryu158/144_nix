## Playwright suite for the interpolation pages

Grew the two smoke tests into 34 specs over `/interpolate_cal` and `/interpolate_blog`. ~8s for the lot. `tests/interpolate_cal.spec.ts` absorbed into `tests/interpolation/calculator.spec.ts`.

Shared helpers so specs stay short: `tests/helpers/grid.ts` (paste/copy/cell), `page-setup.ts` (third-party stubs, consent, console collector), `interp-ref.ts` (fixture loader + reference math), `spec.ts` (spec.json loader).

### The hard rule now runs in a browser
`fixture.spec.ts` pastes `test_in_data.md` into the real page, generates 0..1000 step 1, copies the whole output grid back out, and compares every cell to an independent implementation in `interp-ref.ts` — deliberately a sort-and-scan, not the engine's bisect, because a copy of the code under test proves nothing.
1770 cells, 411 blank rows, max error 5.0e-7. Same numbers as yesterday's Node/numpy cross-check, but through the actual UI.

### Three things that shaped the design
- **The grid is virtualized.** Off-screen rows have no DOM node, so `.gt-cell[data-row="211"]` simply does not exist. Bulk reads go through `copyFromGrid` (Ctrl+A then a synthetic copy event carrying our own DataTransfer, which `_onCopy` fills). No clipboard permissions needed. Waiting for readiness also has to poll the copied data, not a cell.
- **Stub third parties, never abort.** Both pages call `kofiwidget2.init(...)` from an inline script. Aborting the Ko-fi request leaves that throwing ReferenceError, which would poison every console assertion. `route.fulfill` with a two-line stub instead.
- **Decide consent in `addInitScript`.** The banner is `position:fixed` at the bottom and can swallow clicks.
